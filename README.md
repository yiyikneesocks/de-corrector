# @azulores/de-corrector

中文 **「的 / 地 / 得」** 纠错。纯 JavaScript，无原生依赖、无 Python、无网络、无词典配置。

```js
import { DeCorrector } from '@azulores/de-corrector'

const c = new DeCorrector()
await c.warmup()                       // 可选，避免第一条慢

await c.fix('他高兴的跑得很快')
// → '他高兴地跑得很快'
```

## API

### `new DeCorrector(options?)`

| 选项 | 默认 | 说明 |
|---|---|---|
| `maxLength` | `500` | **单块**上限（码点）；超长自动分块，不再整条丢弃（0 = 不限制） |
| `maxTotalLength` | `2000` | 全文熔断上限，超出直接返回原文（0 = 不限制） |
| `chunkTarget` | `300` | 分块目标大小；块越大上下文越好、块数越少 |
| `maxChunks` | `4` | 最多推理块数；超出部分原样保留（不丢文本） |
| `onChunk` | `null` | 分块回调 `(info) => {}`，`info = { total, chunks, processed, skipped }` |
| `modelPath` | 内置模型 | 自定义 ONNX 路径 |
| `debug` | `false` | 输出调试信息 |

### `await c.fix(text)` → `string`

返回纠错后的文本。最常用的接口。

### `await c.check(text)` → `{ text, corrected, changes, tags }`

```js
const r = await c.check('他高兴的跑得很快')
// r.text      '他高兴的跑得很快'
// r.corrected '他高兴地跑得很快'
// r.changes   [{ index: 3, from: '的', to: '地', tag: 'DEV' }]
// r.tags      ['PN','VA','DEV','VV','DER','AD','VA']
```

`changes[].tag` 是 CTB 词性标签，可用来生成解释文案。

### `await c.warmup()`

预热模型。首次调用约 750ms，之后单句 12ms。
建议在插件启动时调一次。

## 它会怎么处理 QQ 里的各种情况

这个库专门针对聊天场景做过加固：

| 情况 | 例子 | 行为 |
|---|---|---|
| 乱打 | `的地得得得得的`、`哈哈哈哈`、`111111` | 不处理 |
| 在「说」这三个字 | `我写了个插件纠正的地得` | 不处理（mention 检测）|
| 连用/手滑 | `他慢慢的地走过来` | 不处理（避免改出"慢慢地地"）|
| 构词成分 | `的士`、`目的地`、`值得`、`土地` | 不处理（冻结词表）|
| 正常错误 | `雨下的很大` | 改（→ `雨下得很大`）|

**设计原则：宁可不改，也不改错。** 误改正确文本比漏改更糟。

---

## 为什么比 jieba 方案好

`@node-rs/jieba` 这类分词器会把 `跑得快`、`说得对`、`做得好` 切成**一个整词**，
导致里面的「得」根本不进入标注，直接漏检。实测 51 句里 **10 句吞字**，
且集中打击 `V得C` 补语结构（「得」最核心的用法）。

本库**不分词，逐字喂模型**。实测逐字输入与「先分词再标注」的词性判断完全一致，
因为模型看的是上下文语法结构，不依赖词边界。

## 体积说明

包内资产 40 MB（模型 26 MB + wasm 15 MB）。
依赖 `onnxruntime-web` 装到 `node_modules` 约 145 MB。

如果觉得重，可以考虑：
- 只在需要时 `import()`（动态加载，不占启动时间）
- 把 `maxLength` / `chunkTarget` 设小一点（如 200），减少单块推理开销

## 精度

与 Python 版 hanlp-lab（完整 HanLP 流水线）逐句对比：**64/64 完全一致**
（在原始 64 条用例上）。

⚠️ **这个数字有误导性**：它表示"JS 端与 Python 端输出一致"，不表示"输出正确"。
HanLP 本身在**专名领属格**上有盲区，两个已知失败模式：

| 输入 | 错误输出 | 原因 |
|---|---|---|
| `赛亚饿的鸟飞的快` | `赛亚饿得鸟飞得快` | 上下文 bleeding：模型把「饿的」误判为补语（conf 0.999） |
| `张本智和地实力` | 不改（应为 `的`） | 模型不认专名，「地」未被识别为候选 |

**v0.1.1 已修复**（邻居规则：的/地/得 后面紧跟名词 → 的，动词+得+名词除外）。
修复后 55/55 测试用例通过。

**v0.1.2 追加**（经 HanLP 原版 tok→pos 验证：以下原版同样改不对，属模型盲区）：
- 固定短语强改：`懂得都懂→懂的都懂`、`总得来说→总的来说`（仅分句首）
- 误改防护：`总的来说` 不再被改成「总地来说」
- 不及物动词程度补语：`他飞的就是高→他飞得就是高`（及物动词/名词化不动）

剩余局限：
- 动词 + 得 + 状态名词（`说得一口好英语`、`跑得一身汗`）依赖例外列表
- 程度补语动词用白名单 `INTRANS_VERBS`，未覆盖的动词可能漏判
- 模型置信度未使用（#6 的 conf 0.999 仍错误）
- 专名检测是启发式，不是 NER

`assets/README.md` 里有模型来源、导出脚本、标签定义。
